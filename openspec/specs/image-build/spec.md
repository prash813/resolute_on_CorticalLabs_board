# image-build Specification

## Purpose
How the Ubuntu 26.04 (Resolute) arm64 server image for Kria SOM boards is produced on an x86 host.

## Requirements

### Requirement: Cross-built classic server image
The image SHALL be built for arm64 on an x86 host using `ubuntu-image classic` from the Kria Resolute image definition (`classic/resolute/ubuntu-server-kria.yaml`).

#### Scenario: Building the image
- **WHEN** the developer runs `sudo ubuntu-image classic --debug -w work -O out classic/resolute/ubuntu-server-kria.yaml`
- **THEN** a bootable disk image for Kria boards is produced in `out/`

### Requirement: Package sources
The image SHALL install flash-kernel from the PPA `sinan-k/xlnx-flash-kernel` and the OEM packages (`oem-limerick-meta`, `oem-limerick-kria-meta`) from the limerick-team PPAs.

#### Scenario: Patched flash-kernel present
- **WHEN** the image is built
- **THEN** the installed flash-kernel is the PPA version that knows the Kria machines and ships `image-kria.its`

### Requirement: FIT image generation
The image SHALL contain a FIT image under `/boot/firmware` generated by flash-kernel from the Kria `.its` template, containing the kernel, the initrd and the Kria device trees.

#### Scenario: FIT regenerated after the build
- **WHEN** the developer runs the hook `hooks/kria/classic/10-flash-kernel-fitimage` on the build output
- **THEN** the FIT image in the boot partition contains kernel, ramdisk and DTB nodes and a configuration for each supported board

### Requirement: Kernel node describes the PE kernel correctly
Because the distro kernel is an EFI zboot PE application, the FIT kernel node used with BSP 2026.1 firmware SHALL use `os = "efi"` and `compression = "none"`.

#### Scenario: KV260 FIT
- **WHEN** the FIT for KV260 is inspected with `dumpimage -l`
- **THEN** the kernel image is reported as an EFI application, uncompressed
